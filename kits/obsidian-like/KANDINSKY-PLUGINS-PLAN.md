### 1. Templater (`templater-obsidian` v2.26.0 — Enabled)
- **Checked by:** Gemini 4 Argon
- **How you use it in The Oracle:** Templater 2.26.0 (data_version: 2) is actively used with `templates_folder: "zMeta/Templates"` and `trigger_on_file_creation_mode: "folder"` (plus `syntax_highlighting: true`, no `user_scripts_folder`, no `startup_templates`, no `file_templates`). It maps 7 folders to templates automatically on file creation: `wiki/sources/books` -> `zMeta/Templates/book.md`, `wiki/sources/papers` -> `paper.md`, `Journal` -> `daily.md`, `wiki/concepts` -> `concept.md`, `wiki/notes` -> `note.md`, `wiki/projects` -> `project.md`, and `wiki/mocs` -> `moc.md` (with 4 additional manual templates in `zMeta/Templates/`: `capture.md`, `category.md`, `meta.md`, `person.md`). Across the 11 template files: 10 of 11 use ONLY three basic Templater tags: `<% tp.date.now("DD-MM-YYYY") %>`, `<% tp.file.title %>`, and `<% tp.file.cursor() %>` (in `note.md`). Only 1 template (`moc.md`) uses a `<%* ... -%>` JavaScript execution block, solely to compute a slugified title variable (`const theme = tp.file.title.trim().toLowerCase().replace(/[^\p{L}\p{N}]+/gu, "-").replace(/^-+|-+$/g, "");`) and interpolate `<% theme %>` in frontmatter (`theme:`, `tags:`) and a heading/Dataview query (`FROM #<% theme %>`).
- **What Kandinsky already has:** Kandinsky has a dedicated, rich, code-free template engine in `crates/kandinsky-template` (`src/lib.rs`, `src/dates.rs`) and deep lifecycle integration in `crates/kandinsky-core/src/notes.rs`, `template_rules.rs`, and `template_values.rs`. Specifically: (1) Native `{{title}}`, `{{date}}`, `{{time}}`, `{{now}}`, `{{day}}` with Moment.js tokens (`DD-MM-YYYY`, `dddd`, etc.) and calendar offsets (`day-1d`, `date+2w`), `{{cursor}}`, `{{include:Other}}`, typed interactive prompts (`{{prompt:Name | choice:A,B}}`, `date`, `number`, `note:folder/`), filters (`slug`, `link`, `join`, `upper`, `lower`, `capitalize`, `trim`, `replace`, `default`, `date`, `first`, `last`, `count`), conditionals (`{{#if}}`, `{{#unless}}`), loops (`{{#each}}`), and plugin-supplied values (`[[tool]] template = "weather"` in `template_values.rs`). (2) Direct Templater syntax compatibility in `notes.rs::templater()` and `templater_tag()` which already evaluates `<% tp.file.title %>`, `<% tp.date.now("fmt", offset, ...) %>`, `<% tp.file.creation_date("fmt") %>`, `<% tp.file.cursor() %>`, and `tp.file.move(...)` after the `{{...}}` pass. (3) Automatic rule matching (`template_rules.rs`) on New Note, Capture, Day Log, Companion Note, and reactive `PropertySet` AST-aware template merging (`atlas-text::merge`), plus fallback reading of `.obsidian/plugins/templater-obsidian/data.json` in `notes.rs::templater_rules()`.

As a result, all 7 of the user's `folder_templates` rules in `data.json` are silently skipped unless copied to `.atlas/config.toml`. (2) Templates folder auto-discovery from Obsidian: `NotesConfig::default()` defaults `notes.templates` to `"templates"`, whereas the user's vault stores templates in `"zMeta/Templates"` (declared in `.obsidian/plugins/templater-obsidian/data.json` as `"templates_folder": "zMeta/Templates"`). If `templates/` does not exist on disk and `[notes] templates` is unconfigured, Kandinsky does not fall back to Templater's `templates_folder`. (3) The `moc.md` slug script block: `moc.md` uses `<%* const theme = tp.file.title.trim().toLowerCase()... -%>` and `<% theme %>`. Because `template_rules.rs::usable()` rejects Templater rules whose file contains `<%*` and `notes.rs::templater()` leaves `<%* ... %>` untouched, `moc.md` won't auto-apply from Templater rules and leaves raw `<%*` tags unless either migrated to Kandinsky's built-in `{{title | slug}}` or shimmed in `notes.rs`. (4) Interactive 'Insert / Merge Template into Current Note' command (`Alt+E` in Templater): Kandinsky applies templates on note creation or when setting a `type` property (`PropertySet`), but lacks a direct command palette action to pick any template from `zMeta/Templates` and insert it at the cursor or merge its frontmatter/sections into the currently open note.
